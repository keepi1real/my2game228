# Инженерный план «Осколков Рассвета»

Актуально: 26 сентября 2026. План двух следующих выпусков: **R1 — v20.1 preview,
надёжность и проверка нового оформления; R2 — v21 preview, развитие героев и карт**.
Это названия выпусков, а не значения `layoutVersion`. Даты выпуска определяются
прохождением критериев ниже; неподтверждённый результат не считается выполненным.

## Исходное состояние

- Стабильная v19 и preview v20 разделены. Новые `interactables` и
  `combat-visibility` скомпонованы локально, на момент составления ещё не опубликованы.
- База — автономный classic-script; патчи добавляются перед `main.js`. Сохранён
  `layoutVersion:16`; новый мир обозначается `mapVersion:20` в checkpoint и
  `journey.v20MapVersion:20` во время игры.
- Preview checkpoint: `undermountain-biomes-v20-preview`; при первом запуске
  импортируется старый checkpoint, если preview-ключ отсутствует. Общий meta Save
  остаётся прежним по текущему контракту; нормальная игра может изменять прогресс.
- Уже есть unit/VM проверки placement (20 seed/глав), storage, lazy loading,
  mobile layout, interactables и combat visibility. CPU-замер поиска угроз не
  заменяет FPS браузера. Старые аудиты описывают состояние до части исправлений.
- Главный инженер проверяет архитектуру и совместимость. Root интегрирует
  manifest/payload/workflow и публикует. Исполнители эти общие файлы не меняют.

### Ворота R1

Все P0 закрыты фактами теста. Browser smoke ловит и `pageerror`, и
`console.error` игрового кадра; проверяет меню и реальный бой, а не только наличие
canvas. Нужны обе мобильные ориентации, 5 героев, 10 глав, v19→v20 import и
v20→v20 resume. Проверяется холодный кэш: новые PNG не загружаются в меню,
отказ PNG не ломает бой. Публикация сначала preview; стабильная v19 остаётся доступной.

### Ворота R2

Результаты R1 остаются зелёными. Карты имеют протокол проходимости, герои —
таблицу измерений, босс — запись фаз/сектора, браузер — отчёт времени кадра.
Новые герои/главы допускаются только с ID, контрактом сериализации и тестовой
сценой. Замена стабильной игры — отдельное решение root после сравнения двух
живых URL; наличие preview не означает готовность stable.

## Интеграционные контракты

1. Один владелец файла. Независимые модули можно делать параллельно; S1 → S2,
   C1 → S2 и новая геометрия → новый save-маркер выполняются последовательно.
2. `interactables` после `readability`, `combat-visibility` после `interactables`.
   Visibility добавляет верхний сигнал после world draw; дизайнерские объекты
   остаются во внутренней сортировке по Y. Обёртки сохраняют this/args/return и
   очищают Canvas/WeakMap scope через finally.
3. Ни дополнительных RAF, ни глобального RNG для декора, ни роста кеша между
   забегами без ограничения. Canvas-представление не сериализуется.
4. `layoutVersion:16` сохраняется: v17/v18 механики проверяют равенство 16.
   Номер релиза нельзя подставлять вместо него.
5. Перед передачей root: список файлов, порядок, точные команды/результаты тестов,
   известные ограничения. Root фиксирует SHA итогового HTML, размеры gzip и
   комплект внешних assets, затем запускает полный browser smoke.

## Следующая выдача задач

1. Техлид берёт R1-S1; до интеграции согласует механизм одной checkpoint-записи.
2. Инженер боя получает R1-C1 отдельным назначением и сначала присылает repro.
3. Уже работающие hero_progression/world_maps завершают только свои малые
   модули и тесты; расширение scope через техлида.
4. После их ответов root собирает кандидат; QA выполняет R1-V1/H1/S2.
   При обнаружении потери checkpoint выпуск блокируется независимо от качества арта.

### Результат текущей передачи

`v20-save-atomic.js` готов: после storage/maps он группирует синхронные checkpoint
get/set внутри saveJourney и делает одну окончательную запись. Meta и legacy
не перехватываются. Unit fault injection и интеграция с настоящим Game прошли:
одна запись, точное восстановление геометрии, quota оставляет прежний checkpoint,
старый v19 checkpoint не меняется. Команды: `node tools/test-v20-save-atomic.js`
и `node tools/test-v20-save-atomic-integration.js`. Root ещё должен включить патч
и выполнить браузерную проверку нативного Storage перед публикацией.

Персональные lvl10-пассивки технически совместимы с Player, но в текущий выпуск
без объяснения в UI **не рекомендованы**. Следующий preview: показать порог и
величину эффекта в карточке героя/прогрессии, затем сравнить Нэму с speed+4% и
базовым вариантом. Малый размер прибавки не доказывает её нейтральность для кайта.
