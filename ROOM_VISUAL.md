# Стражная галерея — комплект оформления

Откройте `room-visual.html`: это готовый интерактивный просмотр оформленной комнаты
на игровом движке из репозитория `keepi1real/my2game228` (исходная ревизия `62b0cb3`).
В меню исходного проекта добавлена кнопка **Стражная галерея · новое оформление**.

## Что собрано

- Новый фон 1536×1024: пол, архитектура и края платформы в едином ракурсе.
- Сине-бирюзовый камень, золотые грани, красные знамёна, крупные спокойные плиты.
- Две отдельные колонны с коллизиями и сортировкой по глубине.
- Восемь живых жаровен, отдельные световые пятна и искры.
- Передний план и прозрачность объектов, перекрывающих героя.
- Три проходимых входа/выхода с сохранёнными координатами прежней галереи.

Это оформление одной полной комнаты. Комплект использует новую живописную основу
и слои рендера; он не является новым генератором этажей. Арена босса не меняется.

## Проверить сейчас

Откройте HTML в настольном браузере. Сервер и интернет не требуются.
Внутри доступны **Осмотр**, **Бой**, **Коллизии**, **Только зал**, **Меню**.
WASD/стрелки — движение, ЛКМ/Пробел — атака, Shift — рывок, 1–3 — умения,
F — зелье. На сенсорном экране используются существующие сенсорные элементы движка.
Проходы в просмотре показывают открытое/закрытое состояние, но не загружают другой
этаж. Сохранённый прогресс обычной кампании при просмотре не изменяется.

## Подключить к проекту

Распакуйте `room-visual-kit.zip`, затем выполните:

```sh
node install-room-visual.js /путь/к/проекту --build
```

Установщик определяет версию по наличию `js/room-floor.js`:

- **Сборка v6:** подключает новое оформление ко всем шаблонам со сценой `gallery`.
  Граф комнат, случайный старт, враги, коллизии и зал босса остаются прежними.
  Создаётся `dist/undermountain-v6-visual.html`.
- **Текущий основной репозиторий:** добавляет отдельный просмотр комнаты в меню.
  Создаётся `dist/room-visual-game.html`.

Исходный `index.html` сохраняется в резервную копию. Старые изображения сохраняются;
отличающиеся пользовательские файлы в папке нового комплекта не перезаписываются.
Повторный запуск не дублирует подключения. В исходниках на HTTPS/PWA после установки
также обновите версию кэша service worker; для собранного HTML это не требуется.

Архив рабочей v6 не сохранился в текущей среде, а на GitHub находится более ранний
движок. Поэтому полный забег v6 с новым оформлением здесь не был запущен. Адаптер
проверен на соответствие сохранённым интерфейсам v6 и сохранность арены босса.

## Слои и маски

Порядок: фон → свет на полу → задние огни → контактные тени → персонажи и колонны
по глубине → передний план → передние огни → частицы. Свет и пламя рассчитываются
отдельно каждый кадр; они не запечены в текстуру пола.

`room-manifest.json` содержит навигационные полигоны, координаты проходов, огней,
масок переднего плана и коллизий. Исходный масштаб — 2/3, камера — (0,32),
экран — 1024×640. Координаты препятствий указаны в игровых пикселях, полигоны
и точки огней — в исходных пикселях 1536×1024.

У исходного PNG колонны нет альфа-канала: генерация вернула фон с клетками.
В рендере применяется измеренная контурная маска `columnClip`, поэтому фон не
попадает в комнату. Для другого движка переносите колонну вместе с этой маской;
не импортируйте исходный лист как готовый прозрачный спрайт.

Изображения созданы встроенным imagegen; финальные промпты сохранены в `PROMPTS.md`.
Коллизии, контурная маска, световые эффекты и порядок слоёв заданы кодом.

## Проверки и сборка

```sh
node tests/run.js
node tools/test-room-visual.js
node tools/test-room-visual-install.js
node tools/package-room-visual.js
```

Проверены связность пола для радиуса героя, все три выхода, движение, столкновения,
слои рендера, бой, смерть, сенсорный рендер и изоляция сохранений. Для Canvas-тестов
нужен `@napi-rs/canvas`. Кадры получены игровым Canvas-рендером под Node; настоящий
браузерный тест не выполнен — загрузка Chromium в среде завершилась ошибкой сети.
Отправки изменений в GitHub не было.
